# HOLBERY — Evidence-gated Offer Framework

2026-10-06 | Ready to evaluate existing offer; not proof that demand exists.

## Required fields

Customer/user/buyer; one observed problem; clear outcome and exclusions; format/version; price hypothesis and actual server price; channel; acquisition cost; delivery/rights; support owner/channel/time cap; refund/service terms; success metric; evidence dates/sample; decision and reversal trigger.

## Current concrete offer

BRS-2026-V1 COMPLETE is already implemented and published, with canonical D1 catalog priceRp99.000, private version-pinned R2 package, owner-approved policies, Duitku production configuration and server-authoritative payment verification. Free tool CTA is relevant and optional, not signup bait or a forced checkout. Do not invent scarcity, testimonials, fake conversion or guarantees.

## Validation flow

Use utility → view result → optional product CTA → read actual offer → genuine buyer decides → existing checkout accepts customer/payment data only where necessary → server verifies payment/provider amount → authorized package delivered → customer acknowledges → feedback/outcome observed. Client analytics must never write PAID, revenue or fulfillment status. No owner-funded fake transaction required.

## No-go / hold

Hold another paid offer when only traffic/clicks exist, rights are unclear, support burden unbounded, outcome unspecified or existing product remains unproven. No new SaaS, CRM, marketplace or automatic subscription. Reuse existing commerce rather than parallel checkout. Refine message/workflow using real feedback before adding products.

## Review

Weekly: opted-in completion/session metrics with limitations, product-interest sessions, actual feedback, verified commerce evidence from protected server records, delivery issues and costs. Label absent denominators N/A and unknown WTP UNKNOWN. Split test traffic. Approve a next experiment, not automatic expansion. Use [review template](UTILITY-REVIEW-TEMPLATE.md).
