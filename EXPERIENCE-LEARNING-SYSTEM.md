# HOLBERY — Experience & Learning System

**Status: CANONICAL KNOWLEDGE MEMORY**

Purpose: convert experience into reusable organizational knowledge without confusing lessons with facts.

## Learning loop
EVENT → OBSERVATION → INTERPRETATION → DECISION → RESULT → LESSON → REUSE TEST

## Experience record
Context/project; intended outcome; action; observed result; what worked; what failed; unexpected behavior; contributing causes; decision; lesson; confidence/limitations; reusable pattern; where reused; date/version.

## Lesson classes
TECHNICAL, OPERATING, CUSTOMER, COMMERCIAL, ECONOMIC, GOVERNANCE, SECURITY, PORTFOLIO.

## Lesson quality
A lesson is stronger when observation is direct, context is explicit, alternatives are considered, it repeats, and another project successfully reuses it.

## Promotion
A lesson becomes reusable KNOWLEDGE or CAPABILITY when it is actionable, evidence-referenced, bounded, and has a practical reuse mechanism.

## Postmortem
Meaningful failures and incidents record intended outcome, actual result, impact, causes, corrective action, prevention, and generalization limits.

## Experience-to-capability
experience → lesson → playbook → reusable capability → second successful use

**Principle:** HOLBERY should get better because it remembers what happened, not because it writes more documents.
