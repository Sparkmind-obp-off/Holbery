# HOLBERY — Operating Manual

**Status: CANONICAL OPERATING PLAYBOOK**

## Operating loop
DISCOVER → VALIDATE → DESIGN → BUILD → LAUNCH → OPERATE → MEASURE → IMPROVE → REUSE / SCALE / RETIRE

Each handoff requires an owner, artifact, evidence boundary, and next decision.

## DISCOVER
Capture customer/user, job, trigger, current alternative, frequency, cost/time, consequence, decision maker, and evidence source. Output: opportunity brief.

## VALIDATE
Choose the smallest safe test. Define hypothesis, sample, timeframe, success threshold, guardrails, and stop condition before running it. Output: evidence record and decision.

## DESIGN
Design the smallest useful delivery. Define journey, inputs/outputs, support burden, rights boundary, and acceptance tests.

## BUILD
Implement only what the validated test requires. Run engineering, security, and data-boundary checks.

## LAUNCH
Confirm owner, rights, delivery channel, support path, terms, onboarding, rollback, and retirement path.

## OPERATE
Record delivery, failures, support, unresolved issues, and user behavior. Keep identifiable records in an approved private system.

## MEASURE
Compare predefined outcomes with baseline. Record numerator, denominator, unit, date range, source, missingness, and limitations.

## IMPROVE
Prioritize the highest-impact constraint. Make controlled changes and preserve before/after references.

## REUSE / SCALE / RETIRE
Reuse proven patterns when boundaries are compatible. Scale only when capacity, economics, and quality support it. Retire when demand, economics, risk, or strategic value no longer justify operation.

## Cadence
Weekly: experiments, feedback, delivery/support, evidence completeness, blockers, decisions. Monthly: portfolio, rights, economics, capacity, retirement candidates.

## Operator checklist
Before: owner, objective, scope, evidence plan, data boundary. During: version, observations, support, incidents, deviations. After: outcome, cost, evidence source, limitations, decision, next action.

**Rule:** if another competent operator cannot explain and repeat the workflow, it is not yet mature.
