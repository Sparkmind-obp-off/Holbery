# 10 — HOLBERY ROADMAP

## Phase 0 — Brand foundation
Status: **COMPLETE / STRATEGIC LOCK**
- Parent identity selected: HOLBERY
- Parent/child architecture defined
- Governance principles established
- Clear boundary from Bozq and Tolvey/Tolva established

## Phase 1 — Foundation repository
- finalize docs
- establish repository structure
- establish brand registry schema
- establish decision log
- establish deployment conventions

## Phase 2 — Parent website / brand presence
Build a lightweight HOLBERY parent presence focused on:
- who HOLBERY is
- what the house owns
- portfolio map
- operating philosophy
- contact / partnership route

The parent website should not pretend to be a marketplace unless the commerce product is ready.

## Phase 3 — Shared platform foundation
Priorities:
- identity / access
- portfolio registry
- product catalog
- shared content model
- basic analytics

## Phase 4 — Commerce engine
Build:
- canonical product source
- SKU management
- order normalization
- payment abstraction
- inventory model
- fulfillment state
- channel adapters

## Phase 5 — First child-brand launch
Choose one child brand with a real commercial reason to exist.

Run the onboarding gates and launch with a narrow offer.

## Phase 6 — Distribution expansion
Add marketplace, social, affiliate, reseller, and B2B distribution progressively.

## Phase 7 — Portfolio intelligence
Build cross-brand dashboards for:
- sales
- margin
- repeat
- acquisition
- channel performance
- product velocity
- inventory risk

## Phase 8 — Group maturity
Introduce more child brands only when shared infrastructure is already reducing cost or complexity.

## Rule for every phase
Do not build infrastructure merely because it is interesting. Build when it removes recurring operational work or unlocks a real commercial capability.
