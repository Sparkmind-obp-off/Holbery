# HOLBERY — Maturity & Readiness System

**Status: CANONICAL GOVERNANCE**

HOLBERY is not mature because it has many documents, code, or deployed pages. Maturity is earned through capability, operation, evidence, economics, and repeatability.

## Six maturity levels

| Level | Meaning | Minimum reality |
|---|---|---|
| L0 IDEA | hypothesis | problem/customer hypothesis exists |
| L1 DEFINED | structurally defined | owner, scope, lifecycle, boundaries and decision path exist |
| L2 BUILT | implementation exists | usable artifact passes engineering acceptance |
| L3 OPERATED | used in real work | real operator/customer can execute the workflow |
| L4 PROVEN | external evidence exists | outcome and/or commercial evidence is observed and recorded |
| L5 REPEATABLE | delivery can repeat | outcome, delivery, support and economics are stable enough to repeat |
| L6 PORTFOLIO-READY | reusable organizational capability | pattern transfers to another legitimate use |

## Maturity dimensions

Review Identity, Architecture, Capability, Evidence, Economics, and Portfolio separately. Status labels: NOT_STARTED, DEFINED, BUILT, OPERATED, PROVEN, REPEATABLE, PORTFOLIO_READY, BLOCKED, REQUIRES_USER_ACTION.

## Readiness gates

**Document-ready:** required artifacts exist and agree.

**Operational-ready:** accountable owner, runbook, support path, rights/data boundary, rollback/retirement path and real operating test exist.

**Commercial-ready:** customer, problem, outcome, offer, price, acquisition, delivery, support and terms are explicit enough for a legitimate offer.

**Evidence-ready:** measurement definitions, source references, sample plan, consent/privacy boundary and decision thresholds exist.

**Commercially-proven:** genuine external paid commitment or transaction evidence exists and economics are measured.

**Repeatable:** more than one legitimate delivery cycle completes with acceptable outcome, support and economics.

**Portfolio-ready:** the operating pattern has been reused or independently validated in a second legitimate context.

**Current master posture: STRUCTURALLY DEFINED / PARTIALLY BUILT / NOT COMMERCIALLY PROVEN.**

## Master readiness rule

HOLBERY becomes materially real when it can demonstrate: coherent parent + canonical library + reusable operating capability + real external outcome + commercial proof + repeatable delivery + second validated reuse.

Child brands are optional outcomes, not a maturity requirement.

## Review

Review after material evidence and at least monthly while active. Record date, authority, evidence, limitations, changed level, and next gate.

**Principle:** maturity is what HOLBERY can repeatedly do, not what HOLBERY can describe.
